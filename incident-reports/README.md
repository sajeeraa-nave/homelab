# Incident Reports

Structured write-ups for security events simulated in Lab 3. Each report documents what happened, how it was detected, and how it was resolved — the same format used in real SOC work.

---

## Report Format

```
# Incident Report — [Short title]

**Date:** YYYY-MM-DD  
**Severity:** Low / Medium / High  
**Status:** Resolved  

---

## Summary
One paragraph: what happened, what was affected, how it was caught.

## Timeline
| Time | Event |
|---|---|
| HH:MM | Description |
| HH:MM | Description |

## Root Cause
What actually caused the incident — not the surface behavior.

## Impact
What was or could have been affected if this were real.

## Detection Method
How it was caught — which Event IDs, which SIEM alert, what the pattern looked like.

## Resolution
Step-by-step: what was done to resolve it.

## Prevention
What would stop this from happening again — configuration change, policy, monitoring rule.
```
